# DiffPlex v115: four accepted runtime improvements

2026-10-20. Compiler commit `66287c45cd5183862a5951199a4b832ea1b30226` on
`codex/profile-v107`. All four proposed families are implemented, reviewed,
validated and committed. The exact source hashes used to regenerate the benchmark
match this commit. The owned core and approved input DLL/PDB are unchanged.

On this local ARM64 character workload, v115 takes **10.87% less
execution time than the retained Unity player** and **13.33% less
than v111**, with correct complete outputs. The .NET gap is still
**4.31×**. This is a measured current compiler
result for the stated workload and machine, not a general claim across libraries
or platforms. These optimizations apply to runtime operation families; no DiffPlex
method names, source pattern replacements or changed input algorithms select them.

uses 1,024 diffs per sample, Unity 4,096 and .NET 16,384. The order rotates and
reverses. Builds, profiling, tests and sanitizers do not overlap these timings.

independent-machine confidence intervals.

## Correctness and budgets

Fresh .NET/v115 verification matches all 523 character and 2,061 line observations,
including checksums 6146 and 3122. Fresh Unity verification matches all 523 character
observations. Each implementation slice additionally passes complete outputs in
release and two O1 ASan/UBSan builds with forced collection and internal/borrow
diagnostics off/on, on a checked 512–576 KiB native thread stack.
The final release timing binary has a largest frame of 432 bytes;
acceptance harness maxima are 544 bytes release, 448 bytes diagnostic-off and
480 bytes diagnostic-on. Binary size is 599,432 bytes versus 568,360 for
v111. The individual frame measurement complements, rather than replaces, the
whole-call-chain stack checks. No quotas or limits were raised.

Shared modules compile as independent translation units without LTO. Focused tests
cover token retirement/collisions, aliasing and output staging, malformed array
storage, readonly and fault order, allocation failure, GC roots, retained handles,
marking limits/stops, scratch failure and string-pool reuse. The collector retains
full inventory and edge validation, checked public ownership and cleanup on failure.

## Next investigation

The [v111 Roslyn/IL2CPP investigation](v111-profile-20261020.md) remains the reference
for exact input/PDB hashes, Release IL tokens/offsets and comparator source/native
traces. It found large line costs in MatchStringSeparator and CopySubstring:
the owned Split scans twice and substring copying creates a temporary integer
array. Unity/.NET retain separator positions and avoid that temporary-copy route.
These are promising shared library targets, but their old profile shares must not
be presented as new v115 shares. Profile committed v115 before selecting the next
change; also remeasure dictionary/collector costs on the character workload.
The extra typed-wrapper experiment remains unimplemented and unaccepted.
