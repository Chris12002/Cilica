# DiffPlex v109: expose primitive reads before larger runtime redesigns

2026-10-20. Committed compiler `9706495`, native v109, on Apple M4 Pro ARM64.
Apple Clang 17, C++20 O2/NDEBUG, no C++ exceptions/RTTI; ordinary .NET 10.0.11.

## Recommendation

**Inline the six tiny array/string read helpers in optimized builds first, then
inline the full array-storage validation helper.** Retain all caller null/bounds
checks and every storage-validation branch; preserve the O0 policy. This exposes
memory reads and checks to Clang so it can combine work inside the already-inlined
kernel graph. Shared modules already contain these runtime bodies in their header.
No new kernel eligibility, ownership shortcut or allocation policy is needed.

The read-only experiment saves **6.66–7.06%** across three batches. Adding full
array-storage-check inlining saves **9.93–10.37%** in the two combined batches.
The final paired comparison is **30.118 -> 26.994 us/diff**, or **10.37% less time**.
The experimental result is **4.98x .NET** in that batch. It is not an accepted
compiler improvement: production remains committed v109 at roughly 5.56x.

The most useful discovery is that typed-kernel inlining did not expose its
primitive reads. Dictionary lookup still contains dozens of calls to tiny
functions that just load a length or element. Removing those boundaries reduces
both calls and native code size. This is broader than a dictionary-only patch.

## Controlled experiments

Every variant matches all 523 retained DiffPlex observations in release. Only the
recommended combined variant additionally received full constrained-stack and
forced-GC sanitizer validation this turn. Do not treat the other variants as
production-ready or add their percentage gains together.

| Experiment | Observed reduction | Assessment |
| --- | ---: | --- |
| Six tiny read helpers, all checks retained | 6.66–7.06% | First implementation target |
| Full array-storage validator inlined alone | 3.38% | Second slice; test interaction |
| Reads plus array validator | 9.93–10.37% | Strongest validated combination |
| Kernel depth passed as a native value | 2.16% | Defer; little additional gain with reads |
| Contiguous descriptor table with exact address/membership checks | 1.16% | Interesting architecture, weak result here |
| Per-frame borrow-retirement flag | 0.69% | Defer standalone; combined result is noisy |
| General string/character allocator inlining | 2.33% | Smaller secondary opportunity |
| Reuse cleared mark state and clear survivors during sweep | 3.35% | Collector candidate requiring invariant tests |

The depth experiment preserves per-path depth-limit checks but carries depth as a
value through the closed no-safepoint graph, instead of repeatedly changing shared
Context state. It cannot be generalized to allocating/callback methods. Combined
with reads it saved 6.96% in the first batch, barely above reads alone at 6.71%.

The descriptor experiment packs 78 real descriptor objects into one table.
Broad predicates reject out-of-range and misaligned candidate addresses before
indexing a static membership mask; they never dereference the candidate. Unlike
trusting an arbitrary header ID, this can retain exact rejection of foreign
addresses. However, its native binary grows and the measured gain is only 1.16%.
It has not received invalid-pointer/shared-module acceptance and should not
supplant the stronger read optimization.

The collector experiment removes a redundant initial mark-clear traversal and
clears surviving marks during sweep. All allocation paths must initialize scratch,
and every failed or reporting-only traversal must still clear it. Inventory,
reference-membership and root validation remain in the experiment. The 3.35% gain
justifies focused follow-up, not immediate shipping without stopped/invalid/limit
and callback-path regression tests.

## Roslyn, .NET and Unity IL2CPP

Roslyn produces the IL operations; runtime/library and native-compiler choices
account for the execution mechanisms below. The input PDB records C# 14.0,
Release/AnyCPU and Roslyn
`5.9.0-1.26379.115+14fbf8d5271c98133561eb55185fdb05b286f578`.
The inspected Roslyn source is the retained comparison revision recorded in the
manifest, not an exact match to that compiler. Actual input Release IL remains
the authoritative lowering evidence.

**Primitive reads.** Roslyn's EmitArrayLength emits `ldlen` with its null semantics;
EmitArrayElementLoad selects the corresponding `ldelem` operation. The exact
owned-core ArrayInterface.Count token `0600007b` contains `ldlen` at IL_0001;
Get token `0600007c` performs an element load. Retained REA body records are reused
only after matching the fresh core's exact hash. DiffPlex BuildModificationData
contains ordinary array lengths, integer loads and element addresses. Cilica
lowers those through its separate length/element helpers, which v109 still marks
noinline. The generated native lookup repeatedly calls them.

Unity 6000.3.2f1's retained generated arrays expose inline GetAt/GetAddressAt methods
with bounds checks and direct element storage. Its dictionary FindEntry body
reads `max_length` directly and obtains inline entry addresses. The implementation
body at Generics__3.cpp:5608 is inspected, not just its forwarding wrapper at 1837.
This matches Unity's [generated-code explanation](https://unity.com/blog/engine-platform/il2cpp-internals-a-tour-of-generated-code).
Cilica should expose its own correctly typed storage to Clang while retaining its
checks, rather than copy Unity's flexible-array representation.

**Borrow/depth bookkeeping.** CharacterChunker.Chunk token `06000021` uses
String.get_Chars at IL_0014, a local address at IL_001a and Char.ToString at
IL_001c. BuildPieceHashes token `06000011` passes its output local address at
IL_007d to TryGetValue at IL_007f. Unity passes native local addresses in the
retained C++; it does not add Cilica's registration-token mechanism. Cilica's
public/stale-carrier guarantees still require validation where carriers exist.
The experiments target internal bookkeeping with proofs, not those guarantees.

**Allocation and collection.** CharacterChunker creates fresh character strings
from source IL. Unity String::NewSize uses pointer-free GC allocation with the
UTF-16 payload in the string allocation; the installed Object.cpp routes this
through GC_MALLOC_ATOMIC under Boehm. .NET describes allocation through a managed
heap pointer in its [GC fundamentals](https://learn.microsoft.com/en-us/dotnet/standard/garbage-collection/fundamentals).
Roslyn itself does not select either collector. Cilica now pools string headers,
but still maintains its own precise inventory, roots, checked marking index and
separate non-string allocations. Those are structural opportunities; increasing
heap limits alone was already weak in the preceding investigation.

**Dictionary layout.** The .NET library and Unity generated code use inline entry
arrays; Cilica's bounded adaptation uses separate DictionaryEntry objects.
That creates 28 entry allocations per diff plus pointer chasing. It remains a
larger design candidate, especially for locality and collection, but this turn
does not implement or measure a semantics-preserving replacement. Mutable key
callbacks, reentrancy, enumeration and reference rooting make it more than a
class-to-struct substitution. Do not attribute all 19.61% dictionary time to it.

## Validation and implementation boundary

The combined read/validator experiment retains all 523 observations in release
and O1 ASan/UBSan forced-GC builds with internal/borrow diagnostics both disabled
and enabled. Every run uses a requested 512 KiB pthread stack and checks actual
512–576 KiB. Maximum native frame sizes remain 432 bytes release and 384 bytes
in both sanitizer builds. No sanitizer diagnostics were emitted.

Production should implement the read helpers and validator as separate reviewed,
benchmarked slices, keeping O0 behavior and validating shared modules, borrowed
arrays, malformed backing storage and managed null/bounds faults. This profiling
turn adds no compiler capability and establishes no new shared-module acceptance.
