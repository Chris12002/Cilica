# DiffPlex v107: small predicate calls and the remaining typed call chain

2026-10-20. Profile of committed `84a3839`, native v107. Apple M4 Pro,
macOS ARM64, Apple Clang 17, ordinary .NET 10.0.11.

## Decision

**Inline the small exact type/interface predicates first, then consider bounded
inlining of the closed typed kernel graph.** Keep every comparison, ownership
boundary, null/bounds check, depth check and fault fallback. This is an emitter /
native optimization opportunity, not a reason to remove managed safety checks.

Small-predicate inlining saves **7.94–9.91%** in two discriminating batches.
The combined small-predicate/kernel experiment saves **12.25%** in the final batch.
Broader predicate/kernel combinations save 13.60–14.27% in preceding batches.
These are diagnostic generated-code experiments; no production implementation is
included and the accepted compiler still has the roughly **6.3x** gap.

Production should inline predicates with fewer than eight descriptors in optimized
builds, updating both declarations and definitions. Keep broad hashed predicates
and the O0 stack-preserving path. Validate public invalid-pointer/descriptor cases,
inheritance/interfaces/array covariance, diagnostic modes and separate modules.
Then evaluate kernel body visibility and an expansion budget before applying
inlining to shared modules: a forward declaration in another C++ unit is not an
available inline body. The existing acyclic depth-eight / 512-statement proof,
managed depth accounting, staged outputs and framed fault replay remain required.

### Why small predicates come first

Seventy predicates use short exact address comparisons; six use descriptor hash
tables. Both kinds are explicitly emitted as noinline. The controlled split shows:

| Experiment, common batch | Median us/diff | Reduction |
| --- | ---: | ---: |
| Baseline | 34.894 | — |
| Only 70 small predicates inlined | 31.437 | 9.91% |
| Only six broad predicates inlined | 34.962 | -0.19% |
| All predicates inlined | 31.394 | 10.03% |
| All predicates plus kernels | 29.915 | 14.27% |
| Fourfold heap/object/string reserve budgets | 34.454 | 1.26% |

The native binary confirms a mechanism, not just a timing correlation: small
predicate inlining reduces static calls to these predicates from **602 to 21**.
Disassembled instruction bytes fall from **273,260 to 263,948**, and executable
size from **590,568 to 570,600 bytes** on this build. Exact comparisons remain;
Clang can combine or eliminate redundant work at callers.

One exploratory variant named `small_predicates` in the first follow-up changed
only definitions and retained noinline declarations. It is an inactive body-only
control, not the small-predicate result. The definitive `small_only` experiment
updates declarations and definitions and distinguishes all 70 small / six broad
predicates explicitly.

### Typed call-chain expansion is second

Clang already inlines most kernels. Four remain as native functions: Dictionary
Find, Equal, HashKey and StringKeyOperations.Hash. Forcing the closed graph inline
saves 6.55% alone in the longer follow-up batch. The final bounded combination
removes all 12 static kernel call sites. TryGetValue's local-output body grows from
424 to 2,336 native instruction bytes because it now contains the graph; the whole
binary's instruction bytes remain slightly below baseline at 271,808.

This is a reason for a bounded expansion policy, not unconditional inlining of
allocating or recursive methods. Shared translation units need additional design
and validation; the experiment does not establish module-wide acceptance.

### Candidates that should not displace these changes

A checked direct bridge to the array-interface Count/Get targets gains only 1.64%
in the exploratory batch. Inlining the general string allocator to specialize its
one-character call site gains only 1.24%. Those are weak effects relative to
observed variation; the array entry validation ablation was also near-neutral in
the preceding investigation. Preserve checks and defer these changes.

Increasing managed object/byte quotas and string reserve fourfold lowers warmed
collections from 21 to 5 over 256 diffs, but gains only 1.26% in the controlled
batch. Peak charged managed bytes rise from 473,136 to 1,819,180; reserved string
slabs rise from 344,176 to 1,302,952 bytes. These overlap occupied managed storage
and must not be summed as RSS. Less frequent collection still scans a larger
inventory. This does not rule out a better collector, but gives no reason to make
larger default budgets the next optimization.

Inline dictionary entries remain a structural opportunity: Cilica allocates 28
entry objects here while .NET/Unity use inline entries. It spans allocation,
locality and traversal, but this turn does not measure a correct replacement.
Do not attribute all 22.24% dictionary time to entry representation or promise that
removing entry allocations removes that entire cost. Re-profile after the measured
predicate/kernel work before choosing a larger dictionary or collector redesign.
