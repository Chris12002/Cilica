# DiffPlex v101: remaining execution costs

2026-10-20. Compiler `a2bb532`, implementation `5440f23`, native v101.
Apple M4 Pro, macOS ARM64, Apple Clang 17, .NET 10.0.11.

## Decision

The remaining gap is distributed. **Fix the empty-array cache's heap membership
scan first**, then carry proven types and local-borrow facts through generated
calls. Repeated type checks are the largest isolated compiler opportunity in these
experiments, but their measured removal is an upper bound, not a completed proof.
Do not enlarge the managed heap as a performance fix for this workload.

Fresh output from the rebuilt committed compiler matches the accepted v101 C++
byte for byte. Release execution is **59.994 us/diff**, versus **5.275 us** for
ordinary non-tiered .NET: **11.37x**. This is a new series, not a revision of the
earlier 11.20x measurement. No production compiler/runtime/core code changed.

## Sampling and work counts

Two three-second samples at one-millisecond intervals contain 5,100 total exclusive
samples, including 4,196 inside the application binary. The following rows are
disjoint and use the application-only denominator.

| Exclusive cost | Samples | Application share |
| --- | ---: | ---: |
| Borrow/location handling and registration | 619 | 14.75% |
| Dictionary bodies, excluding runtime/helper callees | 597 | 14.23% |
| Descriptor predicates | 506 | 12.06% |
| Array representation validation | 375 | 8.94% |
| Empty-array cache lookup | 325 | 7.75% |
| Field-address helper | 103 | 2.45% |
| String hash helpers | 83 | 1.98% |

External code accounts for 904/5,100 samples (17.73%). The character-construction
subtree, including overlapping allocator/GC/helper costs, is now 1,334/5,100
(26.16%), versus 38.06% in the previous investigation. Do not add that inclusive
subtree to the exclusive table or treat sample shares as speedup predictions.

Untimed instrumentation over 256 diffs after eight warmups finds, per diff:

- 143.004 general execution-frame reservations and 141,387 cumulative arena bytes.
  The previous 655.004 reservations have fallen by 512 as intended. These bytes
  are reused storage, not peak live memory.
- 2,568.49 array-layout validations, 16,410 small-set descriptor checks and
  2,643.94 broad-table checks. Hash probe counts vary with native addresses.
- 256 strings, 17 arrays and 39 ordinary objects, including 28 dictionary entries.
- 226 root-chain visits and zero fallback borrow-list visits. Carrier creation,
  validation and conversion remain costly even though the borrow cache works.

251 of 375 array-validator samples come from Dictionary.Find. All 325 empty-cache
samples have a List constructor as their immediate caller. The expensive scan is
the heap-membership check on cached objects, not merely the short empty-array list.
Generated ARM64 has a 236-byte array validator and a 304-byte cache helper.

## Controlled generated-code probes

These are diagnostic transformations of fresh C++, not compiler implementations.
Each passes all 523 observed values before timing. Three processes per variant,
seven samples of 256 diffs per process, at least 300 ms warmup, rotating/reversed
order. C++20 -O2 -DNDEBUG, no exceptions/RTTI, no timing sanitizers. Every checksum
is 6146 per diff. No builds, tests or sampling ran concurrently with timing.
All raw samples, including outliers, are retained.

| Probe | Median us/diff | Less time than paired baseline |
| --- | ---: | ---: |
| v101 baseline | 59.826 | — |
| Array-layout diagnostics off generated execution | 57.574 | 3.76% |
| Cached empty-array references avoid heap-list membership scans | 55.956 | 6.47% |
| Resolve the character borrow once rather than twice | 59.056 | 1.29% |
| Pass a proven local character directly into the rooted helper | 56.566 | 5.45% |
| Remove descriptor predicates inside typed kernels: **upper bound only** | 54.107 | 9.56% |
| Combine array, cache and direct-character probes | 49.467 | 17.32% |
| Also remove kernel descriptor predicates: **upper bound only** | 43.645 | 27.05% |

The last row would still be about 8.27x the fresh .NET measurement. It neither
explains nor solves the whole remaining gap. Gains are not additive.

The cache probe retains owner, known-type, cycle/count, empty-shape and exact
descriptor checks. Internal-reference verification restores heap membership
diagnostics; collector/public checks remain unchanged. The array probe changes
only generated method paths, retaining runtime tracing/borrow/public validation.
Production work must distinguish immutable private-layout diagnostics from
required null/type/bounds checks and preserve diagnostic-mode coverage.

The direct-character probe is restricted to CharacterChunker's known UInt16
local. It preserves both helper depths and real GC frames while avoiding the
temporary carrier. Its fallback remains diagnostic workload tooling; a compiler
implementation needs structural lifetime, escape, type and fault-order proofs.
The descriptor probe removes 66 predicate expressions only from no-allocation
kernel bodies. It preserves null, bounds, exact-dispatch and other checks, but
has no new proof of type correctness. Never apply that text replacement to
production code or infer invalid-input coverage from correct workload output.

The combined array/cache/direct-character probe also passes the complete oracle
on a requested 512 KiB stack, checking 512–576 KiB actual size. Forced-GC O1
ASan/UBSan checks pass with internal-reference verification both off and on,
borrow verification on, and no sanitizer output. Maximum individual frames
remain 432 bytes release and 320 bytes diagnostic. This is bounded workload
evidence, not acceptance of new compiler semantics.

## More memory does not help yet

A separate paired experiment raises both managed-heap limits fourfold:
1 MiB/4,096 objects to 4 MiB/16,384 objects, with matching marking work limits.
It does not alter the native stack or execution arena.

| Configuration | Median us/diff |
| --- | ---: |
| Baseline heap and cache | 60.288 |
| Fourfold heap | 69.449 |
| Baseline heap, cache scan removed | 55.429 |
| Fourfold heap, cache scan removed | 56.965 |

Fourfold capacity is **15.20% slower**, despite reducing collection count.
Removing the cache scan largely removes that regression; even then, the larger
heap is 2.77% slower in this series. That is evidence against increasing this
budget now, not a universal statement that smaller heaps are faster.

Untimed counts over 256 diffs: baseline performs 21 collections, visiting 7,329
reachable objects in total and reclaiming 78,687; fourfold performs five, visits
2,291 and reclaims 79,629. Counts are cumulative and final retained garbage differs.
Observed pre-allocation peaks are 4,096 objects/473,136 charged bytes and
16,384 objects/1,819,180 bytes. These exclude allocator metadata, scratch and
execution storage. The object-count limit, rather than the byte limit, triggers
pressure here. Longer intervals retain more garbage and make heap scans longer.

## Roslyn, .NET and Unity comparison

The input and owned-core DLL/PDB hashes/options remain unchanged and are retained
in identity.json and core build records. Fresh REA metadata inspection ties the
findings to the actual core DLL:

- Dictionary.Find `0600049f`: 129 IL bytes, nine `ldfld`, three `ldlen`, one integer
  array load and one reference-array load. Bucket fields occur at IL_0019/0020,
  entries at IL_0031 and the loop-length field at IL_0076. Recomputing allocation
  byte counts, buffer shapes and descriptor-set membership comes from Cilica's
  generated/runtime checks, not additional source requests.
- TryGetValue `060004a0`: 34 bytes. Input BuildPieceHashes uses `ldloca.s` at
  IL_007d and the dictionary call at IL_007f. Retained .NET ARM64 TryGetValue is
  84 native bytes and writes directly through its output address after FindValue.
- ArrayInterface.Count `0600007b` is four IL bytes; Get `0600007c` is 30. Typed
  array length/access should not intrinsically require repeated layout audits.
- CharacterChunker `06000021` takes the local address at IL_001a and calls
  Char.ToString at IL_001c. Roslyn EmitAddress.cs:288–315 emits a local address
  for a value with a storage home. This does not require Cilica's carrier/token
  representation. .NET's retained native loop uses the character value directly.

The Roslyn checkout is the previously inspected comparison revision, not a
verified exact match for the compiler that built the input. The actual input IL
is the stronger evidence. No new Roslyn compilation or .NET JIT capture occurred.

Pinned .NET Array.cs:1449–1458 returns a per-T static empty array. Unity's retained
Generics__11.cpp:2644–2653 List constructor loads its initialized static empty
array directly. Cilica instead walks the instance cache and checks every cached
reference against the entire live heap. A fix must retain Cilica's per-instance
identity/isolation and GC roots rather than copy a process-global cache blindly.

Unity's il2cpp-codegen.h:810 bounds macro performs an unsigned index/length check.
Generics__3.cpp:5680–5740 reads dictionary entries through typed GetAddressAt
operations. Pinned .NET Dictionary.cs:404–458 uses an Entry[] and a ref entry;
retained ARM64 computes a 24-byte entry address directly. Cilica's
DictionaryEntry is a separate managed class. That adds allocations, indirections
and header/field access, but its independent speed benefit has not been measured.
The 28 entry allocations are fewer than the 256 strings; do not attribute all
allocation time to dictionary representation. Keep this as the next structural
experiment after redundant checks, not a promised speedup.

Source paths and hashes are in reference-sources.json. Unity 6000.3.2f1 evidence
is retained generated/source output; Unity was not rebuilt or retimed. Ordinary
.NET timing is fresh, with tiering and ReadyToRun disabled; NativeAOT is separate.

## Recommended implementation order

1. Remove heap-list scans from trusted empty-cache hits while retaining the
   diagnostic path, per-instance identity, rooting and allocation failure tests.
   This is the smallest well-isolated measured improvement.
2. Propagate validated static-type facts through typed kernels. Validate unknown
   boundaries once, preserve required casts/dispatch/null/bounds semantics, and
   avoid re-proving the same type at every field/array access. Keep private layout
   audits available in diagnostics. The 9.56% result is an opportunity ceiling.
3. Pass proven nonescaping local borrows directly, starting with readonly UInt16
   character construction. Preserve native depth, rooting, aliasing and fault
   order; validate broader out/ref handling independently.
4. Reprofile, then isolate inline dictionary-entry storage and remaining
   allocation/collection costs before proposing a representation rewrite.

All implementation steps need separate correctness and fresh release evidence.
No production edits, hosted jobs or extra agents were used for this investigation.
The emitter remained clean and matched the committed compiler throughout.
