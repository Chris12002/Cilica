# DiffPlex six-backend retime on a quiet host

2026-10-21, `codex/runtime-performance` after native v117 (`a161cf2`). No compiler
change. This replaces the absolute numbers of the loaded-host batches, and adds
default tiered .NET and NativeAOT.

Earlier batches ran beside three orphaned VS Code processes consuming about eight of
fourteen cores. These were removed first. This batch started at a load average of
3.2 and ended at 2.9, from macOS background services only.

## Results

Apple M4 Pro, macOS ARM64. Each backend runs three fresh processes of seven
samples, in one rotating and reversing order. Every timed sample validates its
checksum, and every backend first reproduces all 523 character and 2,061 line
outputs. Medians are in microseconds per diff:

| Backend | Character | Line |
|---|---:|---:|
| Cilica v116 | 21.764 | 35.077 |
| **Cilica v117** | **20.022** | **32.517** |
| .NET 10.0.11, tiering and ReadyToRun off (FullOpts) | 5.239 | 6.703 |
| **.NET 10.0.11, default (tiered, Dynamic PGO)** | **2.485** | **5.637** |
| NativeAOT 10.0.11 (reported separately) | 4.498 | 6.261 |
| Unity 6000.3.2f1 IL2CPP | 24.034 | 23.140 |

Cilica v117 relative to each comparator:

| Comparator | Character | Line |
|---|---:|---:|
| Default .NET | **8.06×** slower | **5.77×** slower |
| FullOpts .NET (previous comparator) | 3.82× slower | 4.85× slower |
| NativeAOT | 4.45× slower | 5.19× slower |
| Unity IL2CPP | 16.7% less time | 1.41× slower |

v116 → v117 takes 8.0% less time on characters and 7.3% less on lines. This agrees
with the loaded-host acceptance batch (−7.35%/−9.51%). Process medians do not
overlap between v116 and v117 on either workload.

## Default .NET and Dynamic PGO

Default .NET does not reach steady state within the 300 ms warm-up of the pinned
DotNetHost. Its character samples fall from about 21 µs to 2.5 µs during timing
while tiered compilation completes. The reference host therefore takes an optional
warm-up; default .NET uses 5,000 ms. A 3,000 ms and a 10,000 ms check both give
flat samples (2.41–2.48 µs and 2.40–2.44 µs). The pinned FullOpts series keeps its
original host and 300 ms warm-up for continuity.

An indicative single-process run with tiering on and `DOTNET_TieredPGO=0` measures
5.048 µs (character) and 6.271 µs (line). That is close to FullOpts, so Dynamic PGO
accounts for most of default .NET's 2.1× character advantage. The likely mechanism
is profile-guided devirtualization and inlining of hot interface and virtual calls.
That is a hypothesis to confirm from JIT disassembly, not an established attribution.
Cilica's closed world could provide much of it statically: exact-target guards,
call-site dispatch caches and getter inlining.

## Comparator configuration

- **FullOpts .NET:** the pinned DotNetHost.dll with `DOTNET_TieredCompilation=0` and
  `DOTNET_ReadyToRun=0`. Comparable with all earlier reports.
- **Default .NET:** the reference host built for JIT with no `DOTNET_`/`COMPlus_`
  overrides and a 5,000 ms warm-up.
- **NativeAOT:** the same reference host published with `PublishAot`, Release,
  osx-arm64, symbols retained. It writes JSON directly, so System.Text.Json and its
  reflection paths are excluded and whole-program devirtualization is not widened by
  host-only types. Benchmark calls and timing match DotNetHost. Its 2.7 MB binary
  reproduces every output. It is a reference only, never a Cilica implementation path.
- **Unity:** the retained Release/OptimizeSpeed player, retimed and not rebuilt.
- **Cilica:** the hash-checked accepted v116 and v117 executables.

These are local process batches, not confidence intervals. Other workloads and
platforms are not measured.
