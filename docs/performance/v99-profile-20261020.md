# DiffPlex v99: the remaining execution gap

2026-10-20. macOS ARM64, Apple M4 Pro, Apple Clang 17, .NET 10.0.11.
Compiler baseline `2906904`, implementation `8f951a5`, native v99.

## Decision

**Optimize character-string allocation first, then its remaining framed wrappers.**
The largest measured subsystem is now the Char.ToString call chain: **38.06% of
all sampled time**, including allocator and collector work underneath those calls.
A bounded one-allocation character-string experiment reduces execution time by
11.85%; combining it with lighter wrappers reduces it by 17.15%. This is stronger
evidence than immediately pursuing array-check or dictionary-layout changes.

Fresh generation from the rebuilt current compiler reproduces accepted v99 C++
byte-for-byte. The new release baseline is **71.839 us/diff versus 5.292 us for
non-tiered .NET: 13.58x**. The earlier 13.46x result is a separate series. No
production compiler, runtime or core-library optimization was made in this
investigation. The emitter rollback described below was restored to committed v99.

## What remains expensive

Two independent three-second samples, at one-millisecond intervals, contain
**3,863 application-exclusive samples out of 5,089 total**. These rows are disjoint
exclusive costs; the character subtree below is a separate, overlapping view.

| Exclusive group | Samples | Share of application samples |
| --- | ---: | ---: |
| Borrow/location validation and registration | 627 | 16.23% |
| Dictionary method bodies, excluding their runtime/helper callees | 497 | 12.87% |
| Descriptor predicates | 411 | 10.64% |
| Array storage-layout validation | 351 | 9.09% |
| Cached empty-array lookup | 290 | 7.51% |
| Char.ToString method bodies | 268 | 6.94% |
| StringKeyOperations hash helpers | 88 | 2.28% |

External routines account for **1,226 / 5,089 = 24.09%** of all samples, mainly
allocation/free and clearing. **1,129** of those external samples lie underneath
Char.ToString. Counting every exclusive sample within that call chain once gives
**1,937 / 5,089 = 38.06%**. This includes collection triggered by character-string
allocation, potentially reclaiming other objects too. It is not an exclusive
38% cost of the two wrapper bodies, and must not be added to the table.

The array validator is the largest individual application symbol. Of its 351
samples, 246 are called by Dictionary.Find. Its 236-byte ARM64 body recomputes
stride, performs an unsigned division for overflow validation, checks charged
allocation size and checks all three backing-buffer shapes. These are repeated
private representation checks around immutable array layout, in addition to
required null/type/bounds checks. The narrow diagnostic experiment below shows
4.34% elapsed-time benefit, less than its sample share; samples are not a speedup
forecast and native layout/inlining also change.

Empty-array lookup's 290 samples all have List construction as the immediate
caller. Cache hits still check heap-list membership before returning a known cache
object. This remains a smaller candidate, with a separately measured 5.79% probe.

## Work counts and native evidence

A separate instrumented binary counts 256 diffs after eight warmup diffs. Its
elapsed time is excluded from performance results. Per diff:

- **655.004 execution-frame reservations**, reserving 399,435 cumulative arena
  bytes. This is reused storage, not simultaneous live memory or managed allocation.
- **256 calls to each Char.ToString overload**: 512 reservations, about 78% of
  remaining frame entries. Their current native bodies are 904 and 720 bytes,
  including cold/fault paths. The corresponding owned-core IL bodies are eight
  and seven bytes; code size is not an execution-time ratio.
- **256 strings, 17 arrays and 39 ordinary objects** allocated. The character
  constructor currently allocates StringObject and its UTF-16 buffer separately.
  No string-result caching is introduced by the experiments.
- **2,568.49 array-layout validations** and **19,053.94 descriptor lookups**:
  16,410 small-set linear lookups plus 2,643.94 broad hash lookups. Hash probe
  counts depend on runtime addresses/collisions and are retained separately.
- **226 root-chain visits and zero fallback borrow-list visits** in this counted
  run. The previous frame/borrow optimization worked; remaining borrow cost is
  largely carrier construction and validation, not searching the fallback list.

Hash, HashKey, Find, TryGetValue and the ordinary string comparer now execute their
typed kernels. Further hand-tuning hash arithmetic is not the next priority.
Dictionary entries remain separate objects rather than inline entries, but this
profile does not isolate the benefit of replacing that representation. In
particular, allocator cost must not all be attributed to dictionary entries.

## Controlled experiments

All experiments transform only generated C++ in the ignored artifact directory.
They are diagnostic prototypes, not accepted compiler implementations. Each
matches all 523 observations before timing. Three processes per variant, at least
300 ms warmup, seven samples of 256 diffs per process, rotating/reversed order:
21 samples per median. Every measured checksum is 6146 per diff. No compilation,
tests or sampling ran concurrently with the timing series; all outliers are kept.
C++20, O2/NDEBUG, no C++ exceptions or RTTI, no timing sanitizers.

| Generated-code probe | Median us/diff | Less time than paired baseline |
| --- | ---: | ---: |
| v99 baseline | 71.202 | — |
| One-character UTF-16 stored inside StringObject | 62.762 | 11.85% |
| Lighter rooted Char.ToString wrappers | 67.049 | 5.83% |
| Both character changes | 58.993 | 17.15% |
| Array-layout diagnostics off generated execution | 68.114 | 4.34% |
| Cached-empty membership ablation | 67.078 | 5.79% |
| Both character changes plus array-layout probe | 56.069 | 21.25% |

The character-combined process medians are 58.344, 58.983 and 59.699 us, versus
71.153, 71.101 and 71.719 us for baseline. The combined character/array probe is
still about **10.60x** the fresh .NET reference. These changes do not close the
whole remaining gap. Effects interact: do not add individual percentages.

The inline-character prototype uses an actual C++ scalar member, preserving object
provenance and fresh string identity. Longer strings keep their original buffers.
It increases the string header size and therefore changes GC pressure; this is a
whole-layout experiment, not a pure malloc microbenchmark. Production work must
review accounting, destruction, UTF-16, identity, allocation failure and all string
construction paths. General contiguous string storage may be a later design;
the measured result supports the bounded character case first.

The wrapper prototype retains depth, carrier validation and small published root
scopes while removing arena-frame setup on the hot nested path. An initial version
incorrectly used the no-safepoint kernel depth guard around an allocating call; the
runtime rejected its root/depth mismatch. It was corrected before timing. This
is evidence that allocation-capable helpers need their own root proof, not simply
a wider whitelist in the current no-allocation kernel analysis. General callbacks,
exception origin/order and arena/depth limits still need focused acceptance tests.

The array prototype disables layout recomputation only in generated method bodies
when internal-reference diagnostics are off. Runtime GC, borrow resolution and
public checks retain their original validation; null, descriptor and bounds checks
remain. The cache probe replaces heap membership on cache hits with internal
managed-reference validation; it weakens private corruption detection and does not
authorize bypassing GC or public-handle checks.

The strongest combined probe additionally matches all 523 observations on a
requested 512 KiB thread stack, verified within 512–576 KiB, in release and two O1
ASan/UBSan builds. Both sanitizer builds force collection before every allocation
and enable borrow lifetime diagnostics; one exercises the array shortcut, the other
restores full internal-reference diagnostics. Maximum native frame is 432 bytes in
release and 320 in these diagnostic builds. This is workload-level evidence, not
general malformed-carrier, allocation-failure or maximum-depth acceptance.

## Next implementation boundaries

1. **Single-allocation character strings:** start with the measured one-character
   representation, preserving separate fresh objects, embedded NUL/surrogates,
   exact accounting, destruction and allocation-failure behavior. Check strings
   created by literals/formatting/copies as adjacent regressions.
2. **Allocation-capable typed character helpers:** preserve real root scopes,
   narrow UInt16 loading, caller storage lifetime, managed depth, faults and result
   rooting. Then consider passing a proven local character directly instead of
   repeatedly constructing and validating its carrier. That extra extension is
   not included in the measured speedup.
3. **Smaller independent runtime costs:** cached-empty membership and immutable
   array-layout diagnostics. Keep public/GC checks and malformed-private-pointer
   diagnostics explicit. Reprofile after the character changes before selecting
   a broader dictionary-entry or allocation-pool project.

Review checked sample denominators and overlap, instrumentation/timing separation,
all output/checksum comparisons, source hashes, native frame evidence and prototype
limitations. No services, hosted jobs, agents or pushes were started.

## Emitter overwrite investigation

The disk emitter again contained the exact old v96 content, SHA-256
`a0da488704d8756d74ce4332a1eb978be3a8e162dabf8abb3df20dcc49918c98`.
Its diff was preserved and the committed v99 file restored before rebuilding.
Fresh C++ matched accepted v99 SHA-256
`e66a1ab85cc5cbf9da55a81f9f29486c80e33ad786d00da6e882265573cc09bd`.
Another recurrence after capture was separately preserved and restored; it did
not change the generated benchmark used for any measurements.

The writer is **not identified**. No open file handle was found; other listed
Cilica Codex tasks were idle, and the inspected recent Claude project log did not
contain emitter writes. Those snapshots do not rule out transient writers. The
filesystem tracing tool requires root, and noninteractive sudo was unavailable.
No unrelated process was stopped or blamed. Repeated identical old content is
consistent with a stale save/sync source, but that remains an inference.

Compact evidence and replay scripts are in
[v99-profile-20261020](v99-profile-20261020/README.md). Large C++, binaries, full REA
output, raw samples and failure logs remain in `artifacts/v99-profile-20261020`.
