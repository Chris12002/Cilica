# DiffPlex after typed helpers: remaining bottlenecks

2026-10-20, macOS ARM64 / Apple M4 Pro, Apple Clang 17, .NET 10.0.11.
Investigation baseline: `74b5d79`, native v97; implementation is `788760a`.
No compiler or owned-library implementation changed in this investigation.

## Recommendation

**Efficient checked descriptor membership is the clearest next bounded change.**
It removes a measured linear-search cost while retaining membership validation.
Then extend typed internal execution into the dictionary lookup path: field reads,
reference results, borrow forwarding and writable local outputs. Those operations
still fall outside v97's deliberately narrow side-effect-free scalar proof.
Do not spend the next slice tuning the already-native string hash arithmetic.

Fresh emission from the rebuilt current branch is byte-identical to accepted v97.
The new baseline is **135.336 us/diff versus 5.171 us non-tiered .NET: 26.17x**.
The earlier 27.49x result remains valid for its measurement series; no implementation
change accounts for this run-to-run difference. In the separate experiment series,
the paired baseline is 140.133 us. Keep the series separate.

## Current profile

Two independent three-second samples at one-millisecond intervals contain
**4,446 application-exclusive samples out of 5,116 total**. The rows below are
disjoint exclusive groups; callers and callees are not counted twice.

| Group | Samples | Share of application samples |
| --- | ---: | ---: |
| Borrow/location resolution and registration, including root-chain validation | 1,175 | 26.43% |
| Generated Dictionary methods themselves, excluding their runtime/helper callees | 1,063 | 23.91% |
| Descriptor predicates | 821 | 18.47% |
| Cached empty-array lookup | 185 | 4.16% |
| Char.ToString method bodies | 135 | 3.04% |
| StringKeyOperations, including the optimized Hash kernel | 23 | 0.52% |

The broad System.Object predicate alone has **679 samples / 15.27%**. Its native
code still loops over 44 descriptor pointers. Its callers include borrowed reference
validation (259 samples), array-location storage (125), marking (123) and reference
array stores (92). This is not permission to disable type checking or GC validation.
A checked address-membership representation can accelerate all of these uses.

Borrow costs include frame-slot resolution, registration and carrier validation;
`active_root_frame` is called from BorrowScope registration. The previous cache
already made fallback token-list searches uncommon. Generic local-address creation,
validation and dereference still happen at each wrapper boundary.

Sampled PCs within dictionary methods repeatedly point to frame reservation /
initialization, carrier copies and root stores. These methods' self time is not
pure dictionary algorithm time. Hash, HashKey, CheckKey, Find, TryGetValue and Equal
alone account for 951 exclusive samples (21.39%). Other Dictionary methods bring
the total to 1,063. Native inspection confirms the mismatch: the nine-byte IL Hash
wrapper has 1,140 bytes of ARM64 instructions; TryGetValue has 1,176 versus 84 in
the retained .NET JIT dump. These sizes include cold/fault paths and are **not**
execution-time ratios. The optimized hash kernel is inlined into its native path.

External system routines account for **670 / 5,116 = 13.10% of all samples**, mostly
allocation/free and clearing. This is a different denominator and not a separate
13% GC estimate. Some collector work is application code. The evidence does not
support replacing the collector as the first next change.

## Instrumented work counts

A separate instrumented executable warms the persistent instance for eight diffs,
then counts 256 diffs. Its timing is excluded from performance results. Per diff:

- About **3,120 frame reservations**, reserving 1,935,603 cumulative bytes.
  Arena space is reused; this is not simultaneous live memory or managed allocation.
- About **18,652 descriptor calls / 89,445 loop comparisons**.
- **6,892 root-chain visits**, versus 63 fallback borrow-list visits.
- **256 strings and 17 arrays** allocated in the warm workload.
- 256 TryGetValue/Find calls; 255 Hash wrappers; 283 HashKey/comparer/hash-kernel
  calls; 228 equality comparer calls. Character construction still traverses two
  Char.ToString wrappers per character.

The full counters, method identities and generated-source hashes are retained.
Counts instrument function entries and can inhibit optimization; they describe
executed work, not the cycle cost of each call in the uninstrumented binary.

## Controlled diagnostic experiments

Each executable matches all 523 .NET output observations and checksum 6146 per
diff before timing. Each variant has three processes, each with at least 300 ms
warmup and seven samples of 256 diffs. Orders rotate/reverse. No builds, profiler
or tests run concurrently with timing. All samples, including outliers, are kept.

| Generated-code experiment | Median us/diff | Less time than paired baseline |
| --- | ---: | ---: |
| v97 baseline | 140.133 | — |
| Collision-checked address hash for descriptor sets of at least eight | 124.979 | 10.81% |
| Native storage for remaining frames, retaining roots and arena-budget accounting | 130.660 | 6.76% |
| Descriptor membership + native frame storage | 114.163 | 18.53% |
| Allow Clang to inline currently noinline helpers | 131.055 | 6.48% |
| Descriptor membership + helper inlining | 116.635 | 16.77% |
| Ablate heap-list validation only on cached empty-array lookup | 136.999 | 2.24% |

Effects interact; do not add or multiply gains. Descriptor-only process medians
are 129.303, 124.979 and 121.743 us; its retained maximum sample is 214.669 us.
Every process median beats the baseline's process medians, but layout/ASLR and
system noise can affect the size of the gain. The cache ablation has overlapping
ranges and weakens private corruption checks; it is a lower-priority diagnostic,
not a proposed implementation. GC cache traversal remains checked in that probe.

The strongest experiment still takes about **22x** the fresh .NET reference.
It matches all 523 observations separately under O1 ASan/UBSan, collection before
every allocation, internal-reference diagnostics and borrow-lifetime diagnostics,
with direct control flow and typed kernels forced on. This is workload correctness
evidence, not general acceptance for malformed inputs, callbacks or maximum-depth
recursion. Native frame size increases from 400 to **2,608 bytes** with native
storage: below the new 4 KiB release review threshold, but whole-call-chain stack
validation would still be required before adoption. Other probes stay at 400 bytes.

## Roslyn, .NET and IL2CPP comparison

Roslyn emits IL; the .NET JIT and IL2CPP/native compiler determine execution shape.
Unity documents that assembly-to-C++-to-native pipeline in its
[IL2CPP introduction](https://docs.unity.com/en-us/engine/6000.3/manual/programming-environment/scripting-backends/il2cpp/il2cpp-introduction).
The detailed comparison below uses actual local sources/generated code, not that
high-level documentation as evidence for specific optimizations.

| Cost | Exact Roslyn IL / .NET evidence | Retained Unity IL2CPP evidence | Consequence |
| --- | --- | --- | --- |
| Repeated descriptor search | Ordinary `ldfld`/array access does not request a scan of all admitted classes. Owned Find token 0600049f has field loads at IL_0007/0019/0020 and subsequent entry reads. Current generated code adds receiver predicates around these operations. | Generics__3.cpp:5608 FindEntry uses typed fields and inline entries. ClassInlines.h:16 performs hierarchy-depth/index comparison; sealed-class checks use class identity. Interface dispatch can still scan interface offsets. | Use efficient checked membership; eliminate repeated checks only with a proven receiver type. Preserve checked public/GC boundaries. |
| Framed wrappers and borrows | Exact input BuildPieceHashes token 06000011 uses `ldloca.s 3` at IL_007d before TryGetValue at IL_007f. Roslyn EmitAddress.cs:288–315 emits the local address. Fresh-core Hash 0600049c uses `ldarga.s` at IL_0001 and call at IL_0003. TryGetValue 060004a0 uses `stobj` at IL_0012 / `initobj` at IL_001a. The retained .NET ARM64 TryGetValue stores directly through its supplied address. | DiffPlex.Benchmark.cpp passes `(&V_3)`. Generics__3.cpp:6967 takes `int32_t*`; lines 6986–6987 load an entry value and write through it. Native locals carry intermediate values. | Extend typed execution to field/array reads, reference results and synchronous writable borrows; retain roots across any allocation and a checked fallback for unproven calls. |
| Comparer wrapper chain | Fresh-core HashKey 0600049d loads comparer at IL_0001/0009 and calls it at IL_0014; OrdinalCaseSensitiveComparer.GetHashCode 060003e0 creates a local address at IL_000e before Hash at IL_0010. v97 cannot prove this entire graph because of field/virtual calls, cold allocation and address forwarding. The measured non-tiered .NET dictionary still uses indirect comparer calls. | FindEntry keeps comparer selection, typed local state and native calls; it is not universally free of virtual dispatch. | Start with a proven exact string/comparer path. Custom comparers may allocate or mutate and must retain their semantics; do not assume every dictionary lookup is pure. |
| Dictionary allocation/layout | Pinned .NET Dictionary.Entry is an inline array struct; native FindValue indexes 24-byte entries. Cilica uses separate DictionaryEntry class objects and pointers. | Generated entry-array access uses GetAddressAt rather than a separately allocated object per entry. | Potential next allocation/locality project, but this investigation does not isolate its speed benefit. Frame/check overhead is already independently measured. |
| Empty cache / character strings | This workload genuinely constructs character strings. Cilica's empty-array cache additionally walks heap membership on hits. | The ordinary typed generated methods do not use Cilica's heap-list carrier scheme. ## Review and next decision

1. **Next bounded implementation:** efficient checked descriptor membership.
   Test null/unknown descriptors, collisions, related/unrelated/array/interface
   types, GC and public handles, module boundaries, and initialization failure
   handling. Choose the final representation for the static catalog; the runtime
   address-hash probe demonstrates cost, not a mandatory production design.
2. **Next larger compiler project:** extend typed calls through dictionary lookup.
   Separate proven hot paths from allocating/callback paths. Include reference
   returns, typed field/array access and writable borrowed locals, with alias,
   exception-order, root-lifetime and full-depth stack tests. Native frame probes
   retain the general calling machinery, so their 6.76% is not a forecast or an
   upper bound for this broader change.
3. **Then investigate allocation layout:** inline dictionary entries and residual
   character/cached-empty overhead. Do not attribute all allocation samples to
   dictionary entries or infer that eliminating them closes the gap.

Review checked fresh-source identity, exact DLL/core hashes, non-overlapping
sample attribution, instrumentation/timing separation, every transcript/checksum,
all retained timing outliers, and comparator limitations. The emitter remained
identical to committed v97 throughout this investigation; that does not diagnose
or permanently resolve the earlier external overwrite. Main is already an
ancestor. No production code, profiles, grants, hosted jobs or services changed.
